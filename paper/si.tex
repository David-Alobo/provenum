\section{Corruption test}
\label{si:corruption}

The value-only and context rows of the main text's corruption table were first measured during
development, and only their totals were recorded. Both were rerun on the original inputs with the
code of that day (Table~\ref{tab:si-corruption}). The context method reproduces the recorded
totals exactly when scored as it was then: 20\% of 562 decimals caught, 88\% where anchored,
and 44 false alarms over all 778 numbers, integers included (29 among the decimals). The
value-only rate recorded at the time, about 1\%, was not reproduced: the rerun catches 2.3\% of
the 562 decimals and flags 4 correct ones. The original settings cannot be recovered, and the
main text now quotes the rerun on the 307 prose decimals, the set the model was tested on.

\section{Security of the review application}
\label{si:security}

The application handles unpublished manuscripts, so it is built to run on the author's own
computer. It listens only on the loopback interface unless told otherwise, stores each session in
a temporary folder that is deleted on request or after six idle hours, and sends nothing to any
other machine unless the author names a model server, which then receives each number's sentence
and paragraph, the candidate cells and the notes.

The server refuses requests from other websites: the \texttt{Host} header must name the server,
which defeats DNS rebinding; requests that change anything must come from its own origin; and
every request body must be JSON, a zip archive or TOML, types a web page can only send after a
cross-origin preflight, which the server never answers. Sessions are addressed by 192-bit random
tokens. Uploaded archives are refused if an entry has an absolute path, \texttt{..}, a colon or a
control character, would land outside the session folder, or if the archive holds more than 5000
files or 200~MB. A specification can only read tables inside the tables folder, and an invalid one
never replaces the last valid one. The model server must be an \texttt{http} or \texttt{https}
address. Responses carry a content security policy that blocks inline scripts, and all text from
the manuscript, tables and model is escaped before display. The model only chooses among cells
whose value already matches, and a cell is applied only after the author accepts it and only if
its value reproduces the written text, so instructions hidden in a manuscript cannot make the
application write anything else.

Each protection has a test (pytest for the server, Vitest for the page). A first review found and
fixed six problems, among them a cross-site form that could start a run sending the manuscript to
any host, and spec paths that could read files anywhere on the machine; a second, independent
review of the hardened code found no further vulnerability at high confidence. The application
has no login and is not suitable for hosting for other people. The full statement is
\texttt{SECURITY.md} in the repository.
